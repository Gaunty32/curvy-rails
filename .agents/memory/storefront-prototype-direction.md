The user approved the separate Curvy Rails demonstration storefront using the supplied logo and predominantly black-and-white homepage direction, and asked that it be optimized mobile-first.

**Why:** The user called the delivered prototype “excellent” and specifically requested mobile-first optimization when asking about external sharing.

**How to apply:** Preserve the approved visual direction during future storefront changes. Prioritize phone usability while retaining desktop support. Do not treat approval of the demonstration as approval to enable live commerce services.

“The only demo site we should be using is this. Once ready we will update the domain.” The user selected the Curvy Rails Storefront Prototype.

**Why:** The user wants one active demo, not multiple competing storefront versions.

**How to apply:** Continue storefront work in the selected prototype. Keep earlier drafts and imported installations untouched unless explicitly asked otherwise; do not create another demo or change the domain before readiness is agreed.

“The patience sold separately t-shirt is perfect for our product template.” Its white version should retain the approved images; its black version uses the supplied cream artwork, with a different plus-size model and a flat shot.

**Why:** The user explicitly approved this product as the template.

**How to apply:** Use the approved product presentation as the reference for future product additions; retain per-colour galleries and separate colour selections rather than combining variants in the basket.
